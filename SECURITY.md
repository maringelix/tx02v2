# Security policy

## Reporting a vulnerability

Report privately through GitHub: **Security > Report a vulnerability** on this repository (private
vulnerability reporting is enabled when the repository is public, see `docs/PUBLICACAO.md`). Do not
open a public issue. Never include credentials, subscription, tenant, object or client IDs, resource
IDs or IP addresses; use placeholders.

This is a personal educational project: reports are handled on a best-effort basis, with no response
time guarantee and no bug bounty.

## Supported versions

Only the latest commit on `main`. There are no releases yet.

## What this repository does to stay safe

The rules, where each one is enforced and the known limits are in
[docs/GUARDRAILS.md](docs/GUARDRAILS.md). In short:

- The harness (`make verify`, also the CI) runs gitleaks, trivy (HIGH/CRITICAL), tflint, actionlint,
  shellcheck, kubeconform and policy checks that block real identifiers, unpinned actions and the
  regressions found in v1.
- GitHub Actions reach Azure only through user-assigned managed identities with GitHub federated
  credentials, one exact subject each; there are no client secrets or storage keys anywhere.
- The CI identities have roles only in the `tx02v2-lab` resource group or on the state container.
  The apply identity may assign roles there only from a fixed list (ABAC condition); Owner and User
  Access Administrator are never assigned, and nothing is assigned at subscription scope.
- Entra ID only: AKS local accounts, the ACR admin user, App Configuration access keys and storage
  shared keys are disabled; Key Vault uses RBAC authorization; PostgreSQL has no public access.
- The database password and the admin token are generated by ephemeral resources and written with
  write-only arguments: they are never stored in the Terraform plan or state.
- Every harness tool is pinned by version and SHA256; actions by commit SHA; the ALB Controller
  chart by SHA256 (its running image digests are checked after install); other images by digest.

## Known limits

v2 has never been applied to Azure (`not run in the cloud (v2)`): the Terraform tests use a mocked
azurerm provider. Inside `tx02v2-lab` the apply identity is powerful (Contributor plus data-plane
roles), and the plan identity can read the Key Vault secret values because the provider refresh
reads them; its federated credentials accept only pull requests of this repository and `main`, and
fork pull requests never get a token. Use a **dedicated subscription**
and keep the `lab` environment protected. Subscription and tenant IDs appear as workflow inputs;
the workflows mask them, but treat the logs as public. With GitHub-hosted runners the AKS API server
must accept `0.0.0.0/0` during a round (Entra ID authentication still applies). See the "Limites"
section of docs/GUARDRAILS.md.
